# Edge Pack Desk

A local, read-only RAG assistant for the public [Edge Pack repository](https://github.com/open-edge-platform/edge-pack) and the official [getting-started guide](https://docs.openedgeplatform.intel.com/dev/platform-software/edge-pack/get-started.html).

The app uses Python's standard library and SQLite FTS5. It can optionally use a local OpenAI-compatible embedding endpoint for semantic search; without one, lexical search remains available. Answers are generated by a local chat endpoint and include repository commit or documentation URL citations. The guide URL is under `/dev/` and may describe work-in-progress behavior; its channel and fetch date are retained in the index.

## Requirements

- Python 3.10 or newer with SQLite FTS5 enabled
- Git
- A local OpenAI-compatible chat-completion server for generated answers
- Optional: a local OpenAI-compatible embeddings server for hybrid retrieval

No Python packages need to be installed. The app, index, source excerpts, and chat UI are local. Only the initial repository and guide sync needs network access; model endpoints must use loopback URLs.

## Quick start

To set up Ollama, download the local models, index the repository, run tests, and launch the app in one step:

```bash
./install.sh
```

The script is safe to rerun: it reuses the Ollama container and existing models, updates the Edge Pack checkout, and avoids stopping services already running. Use `./install.sh --help` for repository, port, saved-guide, and offline-update options. It leaves the web app in the foreground; `Ctrl-C` stops the app while Ollama remains available.

From this directory, fetch the repository and guide and build the index:

```bash
python3 rag.py sync
```

The first run shallow-clones Edge Pack into `data/sources/edge-pack`, fetches the guide, and builds `data/edgepack-rag.sqlite3`. Later runs update the app-managed checkout with `git pull --ff-only` and rebuild the index. If that checkout has local changes, update is refused. Use `--no-update` to index the current checkout without pulling.

If the documentation host is unreachable, the repository index is still built and the guide is clearly reported as missing. To include a saved HTML copy of the page, pass it with `--guide-file`:

```bash
python3 rag.py sync --no-update --guide-file /path/to/get-started.html
```

For an existing checkout elsewhere:

```bash
python3 rag.py index --repo /path/to/edge-pack
```

The index command also fetches the guide. To index only repository files, add `--skip-guide`.

Start the local inference model separately, then set its loopback endpoint and serve the app:

```bash
export RAG_CHAT_BASE_URL=http://127.0.0.1:8000/v1
# Optional when the API does not expose a usable /v1/models response:
export RAG_CHAT_MODEL=Qwen/Qwen3-8B
python3 rag.py serve
```

Open <http://127.0.0.1:8765>. The server binds to `127.0.0.1` only. If your model server uses another port or served model name, set those values accordingly. `RAG_CHAT_MODEL` is omitted by default and the app selects the first model reported by `/v1/models`.

## CPU model with Ollama

This host has no usable Intel render node, so the configured models run on CPU. The model weights persist under `$HOME/.local/share/ollama`; the container API is published on loopback only.

```bash
podman pull docker.io/ollama/ollama:latest
mkdir -p "$HOME/.local/share/ollama"
podman run --detach --name ai-rag-ollama \
	--publish 127.0.0.1:11434:11434 \
	--volume "$HOME/.local/share/ollama:/root/.ollama:Z" \
	docker.io/ollama/ollama:latest
```

Pull the local chat and embedding models:

```bash
curl --noproxy '*' --fail-with-body --silent --show-error \
	--request POST http://127.0.0.1:11434/api/pull \
	--header 'Content-Type: application/json' \
	--data '{"model":"llama3.2:3b","stream":false}'
curl --noproxy '*' --fail-with-body --silent --show-error \
	--request POST http://127.0.0.1:11434/api/pull \
	--header 'Content-Type: application/json' \
	--data '{"model":"nomic-embed-text","stream":false}'
```

Configure the RAG app to use both local APIs, rebuild the index with embeddings, and launch the UI:

```bash
export RAG_CHAT_BASE_URL=http://127.0.0.1:11434/v1
export RAG_CHAT_MODEL=llama3.2:3b
export RAG_EMBEDDING_BASE_URL=http://127.0.0.1:11434/v1
export RAG_EMBEDDING_MODEL=nomic-embed-text
python3 rag.py index --repo data/sources/edge-pack
python3 rag.py serve
```

Ollama can expose both models from one local server; it loads them on demand. If you have a working GPU runtime, you can instead point the same settings at its loopback OpenAI-compatible endpoints.

## Optional embeddings

Set a local OpenAI-compatible embedding endpoint before indexing and serving:

```bash
export RAG_EMBEDDING_BASE_URL=http://127.0.0.1:8002/v1
export RAG_EMBEDDING_MODEL=bge-m3
python3 rag.py index --repo /path/to/edge-pack
```

The embedding API must implement `POST /embeddings` with `encoding_format: float`. The app stores vectors locally and combines vector similarity with SQLite FTS5 retrieval. If embedding calls fail or are not configured, indexing and search fall back to FTS5.

The documented Intel XPU launcher runs one model at a time. Running an embedding model and a chat model concurrently may require another device or a separate CPU embedding runtime; do not assume both fit on one GPU. You can use the app lexically without an embedding endpoint.

## Operations

```bash
python3 rag.py sync                 # Update source and rebuild index
python3 rag.py sync --no-update     # Rebuild from the current app-managed checkout
python3 rag.py index --repo PATH    # Rebuild from another checkout
python3 rag.py serve --port 8765    # Start on 127.0.0.1
python3 -m unittest discover -s tests
```

Set `RAG_DATA_DIR` to move the local checkout and SQLite index. The app does not execute repository content, expose tools, or send source text to hosted inference APIs. Retrieved text is treated as untrusted data in the generation prompt. Verify cited sources for consequential decisions; the model can still produce incomplete answers.

## Scope

The initial index includes allowlisted text files from the repository and the specified getting-started page. It excludes generated output, common lockfiles, binary content, credential-like files, and site navigation/footer content. Other docs, GitHub issues, and release-channel docs are not crawled automatically.
